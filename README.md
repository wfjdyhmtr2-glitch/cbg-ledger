# 藏宝阁台账 · 梦幻西游小号倒卖管理后台

一个给自己用的轻量后台，管理在梦幻西游藏宝阁各区的**小号与商品买卖**：
哪个区有什么角色、花了多少、拆出了什么、卖掉没有、到底赚没赚、钱压了多久。

纯前端 · 零构建 · 零第三方依赖（Vue 3 已内置到 `vendor/`）。
数据全部存放在**你自己的 Supabase 项目**里，登录账号后才能访问。

---

## 一、快速开始

### 第一步：建一个 Supabase 项目（一次性，约 5 分钟）

1. 到 <https://supabase.com> 注册并新建一个项目（免费额度足够用）
2. 左侧 **Project Settings → API**，复制 **Project URL** 和 **anon public key**
3. 左侧 **SQL Editor** → 新建查询 → 把 `supabase/schema.sql` 整段粘贴 → 点 Run
4. 左侧 **Authentication → Sign In / Providers → Email**：
   - 关掉 **Allow new users to sign up**（这样别人注册不进来）
   - 关掉 **Confirm email**（自己的系统，省掉邮箱验证，登录更顺）
5. 左侧 **Authentication → Users → Add user**，手工建你自己的账号，勾上 **Auto Confirm User**

### 第二步：把页面跑起来

```bash
cd 本目录
python3 -m http.server 8765
```

打开 <http://localhost:8765>，填入第 2 步复制的 URL 和 anon key，
然后用第 5 步建的邮箱密码登录，就能开始录数据了。

> 必须用 http 服务器打开，不能直接双击 `index.html`
> （ES Module 在 `file://` 协议下会被浏览器拦住）。

### 第三步：部署上线（可选）

整个目录就是发布产物，不需要构建。把这些传上去即可：

```
index.html
styles.css
src/
vendor/
```

可以拖到任意静态托管（CloudStudio / EdgeOne Pages / Vercel / Netlify / Nginx）。
部署后记得回到 Supabase 的 **Authentication → URL Configuration**，
把 **Site URL** 改成你的线上地址，否则「忘记密码」邮件里的链接会跳回 localhost。

## 二、账号与数据

- 数据存在**你自己的 Supabase 项目**里，不经过任何第三方服务器
- 每个账号只能看到自己的数据 —— 数据库的行级安全（RLS）按 `auth.uid()` 隔离
- 换电脑、换手机，登录同一个账号就是同一份台账
- 页面只是入口，**真正的数据在你的数据库里**，所以 Supabase 账号密码要保管好

> **只填 anon public key。** `service_role` 是管理员密钥，
> 一旦放进前端网页就等于把数据库完全开放，绝对不要用。

如果以后想拉朋友一起用：在 Supabase 里把「Allow new users to sign up」打开，
让他在前台自己注册即可 —— 各账号的数据互相看不到（`owner` 不同）。

## 三、这个后台怎么算账

### 固定资产：自己号的账，独立记

「固定资产」页专门记**自己常玩的号**——按「区 → 号 → 号内物品」三层归置：

- **号本身也是资产**：空号、买来的号都能记购入成本；自己练起来的填 0
- 每个号下挂它里面的装备、召唤兽、灵饰……只归集「购入总成本」，回答"这个号往里砸了多少钱"
- 每个号一张卡：号本身成本 + 号内物品成本 = **这一号的总投入**，区顶上还有区合计
- **完全独立于倒卖核算**：这里的钱不计入投入、回款、盈亏，不出现在价值计算和分析页
- 删号不删物品：号里的东西会变成「未归号」，随时可以归到别的号名下

### 区服不用维护：它从数据里自己长出来

区服不是一个要提前建好的清单。角色和商品上各自记着区服名，
后台自动把出现过的区服汇总成列表 —— **你录到哪个区，哪个区就自动出现**。

- 「区服」页是只读的，没有新增 / 改名 / 删除
- 展开任何一个区，直接透出该区下的角色和商品明细
- 录入时输入框会自动补全已经出现过的区服，防止手滑打成两个名字
- 有转服的情况：买入区算成本和成交；成交区只标注「↓ 转入卖出」

### 核心模型：角色 = 一票生意（项目批次）

角色在藏宝阁里本身就是个能转手的资产，而且是个「容器」：

```
买入角色 ¥8600
   ├─ 整体转手卖出              → 直接成交
   ├─ 拆号：装备/召唤兽单独上架   → 各卖各的
   └─ 拆完剩下的「空壳号」还能再卖 → 又是一笔
```

所以后台把**角色当成核算单元**：所有从它身上拆出来的商品都挂在它名下（`role_id`），
这一票赚没赚，看的是

```
已回款（本体 + 拆出商品 + 空壳）  +  手上还剩的东西估值  −  总投入
```

**不用你手工摊成本**，母角色那一行就是这票的总账。

### 两种视角，随时切（右上角）

| | 项目视角（默认） | 单品视角 |
|---|---|---|
| 成本归属 | 全算在角色这一票上 | 按估值权重摊到每件商品和空壳号 |
| 回答的问题 | 「这一票赚没赚」 | 「到底哪件在赚钱、哪件是搭头」 |
| 拆出商品 | 成本列显示「—」 | 显示分摊成本，能算单件毛利 |

两个视角的**总盈亏是一致的**，只是拆分方式不同。切换不改数据。
成本会按各资产的估值权重自动摊，也可以用 `allocated_cost` 字段手工指定。

### 转服卖跨区怎么记

登记售出时，「成交时所在区服」可以填一个不同的区（输入框会自动补全已有区服）。

**整票（成本和成交）都归到买入区** —— 同一笔生意不该被拆成两半，否则买入区看起来巨亏、
卖出区看起来暴赚，两个区的数字都失真。所以：

- 买入区：投入 + 成交，看得出这一票的真实盈亏
- 卖出区：**不重复计入**，只在卡片上标注「↓ 转入卖出 ¥X」，方便你看这个区的出货能力

区服卡片上还会有「↑ 转出卖出」，表示在这个区买入、转到别区卖掉的成交额。

### 价值计算：这个成本要挂多少钱才不亏

「价值计算」页回答一个问题：**给定购入成本，最少要挂多少钱卖才能保本。**

- 成本直接填（记得把转服费、杂费一起算进去），也可以**从持仓里选一条自动带入**，带入后照样能改
- 保本挂牌价按真实费率反推 —— 角色的 60 元保底、1000 元封顶这些边界都算进去了，
  挂到那个价，税后到手一定 ≥ 成本
- 附一张目标价速查表：从 -10%（割肉出）到 +50% 各档的建议挂牌价
- 反过来填一个挂牌价，实时显示到手多少、赚还是亏

### 手续费（已内置，按官方规则）

全部由**卖家**承担，买家不收费；不足 1 分按 1 分收：

| 类别 | 费率 | 上下限 |
|---|---|---|
| 角色 | 5% | 最低 60 元，最高 1000 元 |
| 装备 / 召唤兽 / 灵饰 / 未鉴定装备 / 宝石 | 5% | 最高 1000 元 |
| 梦幻币 | 5% | 无上下限 |
| 礼盒礼币 | 10% | 无上下限 |

登记售出时后台会自动算到手金额。如果实际到账有出入（比如转服时间锁的特殊服务费），
直接在「实际到手」里填真实数字，以你填的为准。

### 在手资产怎么估值

未卖出的东西按这个优先级估值：**你填的「估算市值」→ 挂牌价扣掉信息费后的到手额 → 买入成本**。
想保守就填低一点，账面的「预计盈亏」也会跟着变保守。

**例外：已拆号、只剩空壳的角色。** 它的价值已经转移到拆出去的装备召唤兽上了，
如果既没填估值也没挂价，就按 **0** 计 —— 宁可显示成「还没回本」，
也不拿买入全价当空壳残值把盈亏虚抬上去。首页会提醒你有哪些空壳号还没估值，补填一下账就准了。

### 三个盈亏口径

- **已实现盈亏**：已经卖掉的部分，成交到手 − 分摊成本。落袋的。
- **浮动盈亏**：还在手上，估值 − 成本。没卖就还会变。
- **回本进度**：已回款 ÷ 总投入。到 100% = 本金全收回来，剩下的持仓都是利润。

## 四、安全

- 数据访问靠 **Supabase Auth 登录 + RLS**：未登录的匿名请求完全没有任何权限，
  已登录用户也只能读写 `owner = 自己` 的行。
- anon key 会出现在网页源码里，这是正常的 —— 它本来就是公开密钥。
  真正把门的是登录态和 RLS，不是这个 key。
- **务必关掉「公开注册」**（快速开始第 4 步）。否则任何人都能注册账号进来。
  虽然读不到你的数据，但会往你的数据库里写垃圾。
- 部署到公网时记得在 Supabase 配好 **Site URL**，并建议开启邮箱验证与强密码策略。
- 任何时候都不要把 `service_role` key 写进前端。
- 数据在云端也**建议定期「导出 JSON」留一份本地存档**，防手滑。

## 六、常见问题

**Q：能不能多人一起用？**
可以。在 Supabase 打开「Allow new users to sign up」，让朋友自己注册。
每个账号只能看到自己的数据（按 `owner` 隔离），互不干扰。
如果你想的是几个人**共用同一份台账**，那需要共用同一个账号登录。

**Q：数据会不会丢？**
数据在 Supabase 云端，不会因为清缓存、换电脑而丢。
但仍然建议**每周「导出 JSON」**留一份本地存档 —— 万一误删能有据可依。

**Q：登录提示密码错误，或者注册后进不去？**
- 密码不对：Supabase → **Authentication → Users** → 选中你的用户 → Reset password 直接改
- 注册后登录不了：多半是开着「Confirm email」。可以在 **Users** 页面点该用户勾上
  Auto Confirm，或者到 SQL Editor 执行
  `update auth.users set email_confirmed_at = now() where email = '你的邮箱';`
- 忘了密码又没配 Site URL：同上，直接去 Users 页面重置最快

**Q：想改手续费费率？**
改 `src/core/fee.js` 里的 `calcFee()` 就行，其他地方都走它。

**Q：想加字段（比如代练成本、账号来源）？**
改三处：`src/core/model.js`（工厂函数默认值）、
`src/components/forms.js`（表单）、`supabase/schema.sql`（建表 + 数据库里 alter）。

**Q：改了代码刷新却看不到效果？**
浏览器对 ES 模块的缓存很顽固。强制刷新即可：
macOS `Cmd + Shift + R`，Windows / Linux `Ctrl + Shift + R`。
